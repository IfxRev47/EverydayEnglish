# AI 聊天与自定义 Skill（App 1.3）

App 1.4 新增 [模型参数与 AI 语音](模型参数与AI语音.md)。下文的 2048 上下文、384 回复 token 和 2 轮记忆现在是默认值，可在「参数 / 语音」修改；手动和自动朗读也在新版接入。

## 使用

首页点击「AI 助手」进入聊天。首次使用点击「模型 / 造句」，导入并加载兼容的 GGUF 指令模型，再点击「进入 AI 聊天」。聊天和造句共用一个模型，无需重新导入或重复占用两份模型内存。

在底部输入消息后发送。回复逐步显示，可以长按复制文本、点击「停止」，或在空闲时点击「新对话」清空聊天。离开聊天页面或进入后台时停止当前任务，旋转屏幕保留当前页面状态。进程退出后聊天记录不保留；已导入模型与自定义 Skill 保留。

## 短上下文规则

- 默认上下文仍为 2048 token，回复最多 384 token，不增加上一版本的上下文内存配置。
- 每次发送：当前 Skill ＋最近最多 **2 轮完整问答**＋本次消息。
- 对话按真正的 user / assistant 角色套用模型自带的聊天模板，不把所有历史拼成一条伪对话。
- JNI 使用模型的 tokenizer 计算模板展开后的实际 token 数。输入预算最多 1664 token；超过时按整轮删除最早的问答，再重新计算。Skill 会重新附加到保留的第一条用户消息，不随旧历史丢失。
- 如果只剩 Skill 和本次消息仍超过预算，提示缩短输入或 Skill，不截断规则或本次问题。
- 消息最多 800 个字符；字符数不等于 token 数，中文或特定模板仍可能超出预算。
- 已停止、失败、空白回复不作为后续上下文。界面最多显示最近 20 轮，显示范围与模型实际记忆范围不同。
- 每次推理清空 KV 上下文后重建短对话；造句与聊天内容不会互相混入。

## 自定义 Skill

Skill 在这个 App 中是**角色和回答规则的提示文本**，不是 Codex 插件、工具调用或可执行脚本。

内置「英语陪练」使用简单英语、简短中文解释、温和纠错与一个后续问题。点击「添加 Skill」，填写名称和内容后「保存并使用」。例如：

名称：日常口语教练

```text
你是我的日常英语口语教练，我的水平为 A1～A2。
每次只问一个日常问题，使用简短、自然的英语。
如果我的回答有错误，先给出修正后的句子，再用一句中文解释。
最后问一个相关的问题。不要一次输出长篇课程。
```

也可以粘贴自己准备的 Markdown 规则。当前版本通过文本编辑添加，不提供文件导入或脚本运行。自定义 Skill 可编辑和删除，内置 Skill 保留不变。最多 20 个，名称最多 30 字符，内容最多 1200 字符。

保存、删除、切换 Skill 均会清空当前对话，使用新规则开始；生成时禁止修改 Skill。模型是否严格遵循规则取决于所用模型。为兼容不接受 system 角色的模板，Skill 放在第一条保留的 user 消息前；不修改模板本身。

## 程序结构

| 文件 | 新职责 |
| --- | --- |
| `ai/ChatScreen.kt` | 聊天列表、输入框、停止、新对话、Skill 选择与编辑对话框 |
| `ai/ChatData.kt` | ChatTurn / ReplyStatus、两轮上下文选择、SkillSettings 与 SkillStore |
| `ai/AiViewModel.kt` | 复用模型生命周期；管理流式聊天状态、Skill 保存及失败/中断标记 |
| `ai/LlamaNative.kt` | JNI 接收 UTF-8 消息数组和独立 Skill 内容 |
| `cpp/native-lib.cpp` | 多角色模板、实际 token 预算与逐轮裁剪、原有 CPU 推理 |
| `MainActivity.kt` | 词库、AI 聊天、模型/造句页面之间的切换 |

Kotlin 路径相对 `app/src/main/java/com/oxford/a1/`；原生路径相对 `app/src/main/`。

Skill 及选中项以 `filesDir/chat-skills.json` 本地保存，使用 Android AtomicFile 写入；校验失败不会覆盖旧设置。聊天记录只在 ViewModel 内存里，旋转保留，进程退出清空。不新增 Room 表，不修改 `vocabulary.db`、词库 JSON 或 learned 字段。

App 版本为 1.3 / versionCode 4，仍为原包名和本机签名。直接更新安装即可保留词库学习记录、模型副本和 Skill。

## 继续扩展

- 调整记忆轮数：`ChatContext.HISTORY_ROUNDS`，同步调整 JNI 消息数组数量上限（当前最多 5 条）。不能只提高轮数而忽略 2048 token 总预算。
- 调整输入上限：`ChatContext.MAX_INPUT`；Skill 长度上限在 `SkillStore.MAX_INSTRUCTION`。
- 增加内置角色：修改内置 Skill 目录和 UI 选择项，使用固定稳定 ID，避免覆盖用户创建的条目。
- 若要持久化聊天历史，应另建存储，保留完成/中断/失败状态；仍只取短窗口送给模型，不把全部日志塞进上下文。

模型加载和设备条件见 [离线模型与造句](离线模型与造句.md)。自动化测试不代替真机推理；当前没有连接设备或提供实际模型，聊天质量、多轮模板兼容性及运行速度仍需真机验收。

# 离线模型与造句功能（App 1.2）

App 1.4 已加入 [模型参数与 AI 语音](模型参数与AI语音.md)，下文的固定推理参数现在可以通过界面调节，生成结果支持英语 TTS 朗读。

App 1.3 新增 [AI 聊天与自定义 Skill](AI聊天与自定义Skill.md)。当前入口为首页「AI 助手」→「模型 / 造句」，模型管理和造句用法保持不变。下文记录 1.2 的基础实现；新 JNI 已扩展为消息数组，聊天支持短历史，造句仍使用单条请求。

## 使用方法

1. 更新安装新版 APK，保留旧应用，不卸载、不清除数据。
2. 在词库里标记已掌握的单词，点击顶部「离线造句」。
3. 点击「导入 GGUF 模型」，从系统文件选择器选择自己准备的单文件 `.gguf` 指令/对话模型。App 复制一份到内部存储，不修改原文件。
4. 点击「加载模型」，等待状态变为已加载，再点击「用已掌握单词造句」。每轮随机选最多 5 个已掌握词，提示模型输出 3 个简单英文句子及中文翻译。
5. 可以反复生成、停止当前操作、复制输出、释放模型内存，或删除 App 内模型副本。

这里集成的是项目已有的 **llama.cpp**，共享库保留 `libollama.so` 名称。它直接在手机 CPU 上推理，无需安装或启动 Ollama 服务、填写服务器地址或连接电脑。App 不包含模型、不自动下载模型、没有 INTERNET 权限。

## 模型格式与设备限制

- 接受 GGUF v2/v3 单文件模型；文件名/扩展名不是判断依据，先检查实际文件头，再由 llama.cpp 加载时检查完整格式和架构。
- 使用 Instruct/Chat 模型，且 GGUF 内带有当前 llama.cpp `llama_chat_apply_template` 支持的对话模板。不支持的模板会明确报错，不会套用猜测的模板。缺少模板的基础模型、分片 GGUF、`.safetensors`、Ollama 模型标签/清单不能直接使用。
- 支持导入 3～4B 量级的量化小模型，也可导入更小模型；这不是对所有 3～4B 模型或所有手机的运行保证。模型架构支持取决于项目内这份 llama.cpp，内存不足可能被 Android 直接终止。
- APK 当前仅包含 `arm64-v8a`，要求 64 位 ARM Android 8.0 及以上设备；不包含 x86 模拟器库。模型文件大小不等于运行内存占用，加载时还要分配上下文和计算缓冲区。
- 当前导入上限 8 GiB，复制过程中保留至少 128 MiB 存储余量。替换时需要同时容纳旧模型和新模型副本的存储空间；这项余量检查不是运行内存检查。
- 未连接真机，也没有提供模型文件；目前完成的是源码编译和自动化回归，不代表已完成 3～4B 模型真机性能测试。
- 模型文件按其发布者许可证自行获取和使用；llama.cpp 的 MIT 许可证不授予模型权重授权。不要把未获许可的权重提交仓库或放进 APK。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `ai/OfflineLearningScreen.kt` | Compose 页面、系统文件选择器、加载/释放/停止/删除按钮和流式输出 |
| `ai/AiViewModel.kt` | UI 状态、后台任务串行化、取消、错误说明和生命周期清理 |
| `ai/ModelStore.kt` | 流式复制、文件头校验、磁盘空间检查、原子替换和模型删除 |
| `ai/LearningPrompt.kt` | 从 `Word.learned` 为真的词中随机选最多 5 个目标词，构建学习提示 |
| `ai/LlamaNative.kt` | Kotlin JNI 入口，用户主动加载时才装载原生库 |
| `cpp/native-lib.cpp` | 加载 GGUF、套用模型模板、分批处理提示、采样、UTF-8 输出和停止 |
| `cpp/CMakeLists.txt` | 构建 CPU 推理所需的库，关闭服务器、工具和示例目标 |
| `assets/licenses/llama.cpp-MIT.txt` | 随 APK 分发的引擎许可证 |

上述 Kotlin 路径相对于 `app/src/main/java/com/oxford/a1/`；`cpp` 和 `assets` 相对于 `app/src/main/`。vendored llama.cpp 源码保持原样。

数据流：Room 单词流 → 原有 WordViewModel → 当前已掌握单词快照 → LearningPrompt → AiViewModel 的 IO 任务 → JNI → llama.cpp → UTF-8 累积输出 → Compose。

本轮目标词只是提示约束，小模型可能遗漏目标词、使用新词或输出不准确翻译。允许基本功能词和词形变化，不声称输出严格仅含已掌握词。生成内容只存在页面状态中，不写回学习记录；进程重启后会消失。

## 存储与升级安全

模型固定保存在 `Context.noBackupFilesDir/models/active.gguf`，显示名称为同目录的 `name.txt`，不进入 Android 云备份。一次保留一个模型；再次导入就是更换。用户文件名只用于显示，不用于构造目标路径。

导入先写 `import.part`，使用 1 MiB 缓冲区逐块复制，不把整个模型读入 Java 堆。文件头校验、复制、空间检查全部成功后，通过同目录 `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)` 原子替换 `active.gguf`。取消或失败会删除临时文件，原模型仍可重新加载。异常进程退出可能留下临时文件，下次导入会覆盖它。

更换模型前先释放当前引擎。模型副本删除与单词数据库互相独立。版本 1.2 仅将 APK `versionCode` 增为 3，Room 仍为版本 2，数据库仍为 `vocabulary.db`，A1/A2 数据包版本不变。没有重建数据库、清除学习状态或新增 destructive migration。

## 推理参数与拓展位置

原生默认值：CPU 推理，最多 4 线程；上下文 2048 token；预填充批次 128；最多输出 384 token；top-k 40、top-p 0.9、temperature 0.65。这些值位于 `native-lib.cpp`，线程数上限位于 `AiViewModel.kt`。原生库在 debug APK 中也使用 Release 优化，Android/Kotlin 部分仍为 debug 构建。

每次生成都会清空上下文，不累积聊天历史。停止使用原子取消标记，并接入模型加载进度回调和解码 abort callback；操作在 IO 线程串行执行。底层某些初始化阶段未提供中断点，停止可能要等待该阶段返回。退出页面或真正进入后台时停止任务；屏幕旋转继续保留 ViewModel。模型加载后保留在内存，点击「释放内存」可以显式卸载，Activity 最终销毁时也会清理。

如要调整造句风格，修改 `LearningPrompt.build`；要增加词义提示，可从传入的 Word.meanings 选取，但应保持提示长度有限。要加入模型列表，需要把 ModelStore 的固定单文件改成受控目录内的多文件索引，继续使用流式临时文件导入和原子提交。若要增加输出长度，要同时检查上下文预算和设备内存，不能只提高输出循环上限。

扩展词库沿用 [程序结构与词库扩展](程序结构与词库扩展.md) 的流程。新增 B1/B2 单词被标记已掌握后，会自动参与造句，无需修改模型层。

## 构建与验收

依赖 NDK `28.2.13676358`、CMake `3.22.1`、项目原有 JBR 21 与 SDK。Android Studio SDK Manager 中安装对应版本，然后执行 README 中的 Gradle 命令。

真机验收：更新安装保留标记 → 选择合法兼容 GGUF → 飞行模式加载 → 连续生成中文/英文 → 生成中停止 → 旋转屏幕 → 切到后台 → 释放并重载 → 取消/失败替换后重载旧文件 → 删除模型后确认学习记录仍在。请记录手机型号、可用内存、模型名称/量化类型、加载耗时与生成速度，再决定是否增大参数。
